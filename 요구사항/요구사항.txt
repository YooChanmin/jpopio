🎵 프로젝트: 멀티플레이 음악 퀴즈 웹게임 (가제)
컨셉: Scribble.io 스타일의 UI/UX를 차용한 실시간 음악 맞추기 게임. 핵심 전략: 서버 비용 최소화(DB 미사용 리스트) 및 구글 애드센스 수익화 최적화.

1. 메인 화면 (OFF GAME - Landing Page)
사용자가 처음 접속하는 화면입니다. PDF의 3단 구성 과 Showdown 스타일의 리스트 관리 시스템을 포함합니다.

A. 화면 레이아웃 (3-Column)
좌측 (Profile & Ads):

커스텀 프로필: 닉네임 입력창. 좌우 화살표 버튼(< >)으로 아바타의 눈, 입, 색깔, 장신구를 조합하여 캐릭터 생성.

좌측 광고 영역: 세로형 구글 애드센스 배너 (수익화 핵심).

중앙 (Game Entry):

메인 로고: 게임 타이틀.

게임 시작 버튼: 클릭 시 '방 만들기' 또는 '빠른 입장'.


게임 가이드: 팝업 형태로 게임 방법 설명.

하단 푸터: 인스타그램 아이콘, 제작자 정보.

우측 (List Builder - Showdown Style):

리스트 메이커 (Builder): 유저가 직접 퀴즈 리스트를 제작하는 패널.

우측 광고 영역: 하단 자투리 공간 활용.

B. 리스트 메이커 기능 (핵심)
서버 저장이 아닌, 로컬 텍스트 기반 관리 시스템입니다.

입력 폼:

YouTube URL (링크 자동 파싱)

Start Time (재생 시작 지점, 초 단위)

Answers (복수 정답 태그 입력, 엔터로 추가. 예: [Hype Boy], [하입보이])

Hint (텍스트 입력)

동작:

[Add]: 곡을 리스트에 추가 (아래에 카드 형태로 쌓임).

[Export]: 작성된 리스트를 JSON 텍스트로 변환.

Plan A: 텍스트 박스에 출력 → 클립보드 복사.

Plan B: .txt 파일로 즉시 다운로드.

[Import]: 기존에 만든 텍스트나 파일을 불러와서 수정 가능.

2. 게임 대기실 (Waiting Room / Lobby)
방을 생성하면 이동하는 공간입니다. 게임 시작 전 전략을 짜고 설정을 조율합니다.

A. UI 구성
상단: [초대 링크 복사] 버튼, 방 제목.

중앙 (Stage): 접속한 플레이어들의 아바타가 대기하는 모습.

좌측 (Player List): 접속자 목록 표시. 방장은 여기서 비매너 유저 강퇴(Kick) 가능.

우측 (Settings Panel - 방장 전용):


리스트 불러오기 (Import): 제작한 .txt 파일을 업로드하여 게임 데이터로 적용.


라운드 수: (예: 10 / 30 / 50곡).

제한 시간: 곡당 재생 시간 (예: 30초 / 60초).

힌트 설정: ON/OFF 및 등장 타이밍.


스킵 투표율 (Skip Threshold): 과반수(50%) / 70% / 전원(100%) 설정.

채팅 모드: 분리 모드 vs 검열 모드 선택.


[GAME START]: 모든 설정 완료 시 게임 시작.

3. 인게임 진행 (IN GAME - Loop)
설정된 라운드 수만큼 [퀴즈 → 정답 공개] 사이클을 반복합니다.

A. 퀴즈 진행 (Playing State)
화면 연출:

가운데 아바타들이 음악에 맞춰 춤추거나 DJ 모션, 노래방 책 뒤적이는 모션 재생.

상단: 현재 라운드(1/50), 남은 시간 타이머, 스킵 투표 현황(0/5).

오디오: 유튜브 영상은 숨겨지고(Hidden) 소리만 재생.

힌트 시스템:

설정된 시간(예: 남은 시간 50%)이 되면 힌트 텍스트가 타자 치듯(Typewriter) 한 글자씩 공개.

채팅 및 정답 처리:

별도 정답칸 없이 채팅창에 입력.

정답 판정: 띄어쓰기, 대소문자, 특수문자 무시(Normalization) 후 비교.

채팅 분리 (설정에 따름):

분리 모드: 정답자는 미정답자의 채팅을 볼 수 있지만, 미정답자는 정답자의 채팅을 볼 수 없음 (단방향 투명 유리).

검열 모드: 정답자가 입력한 정답 유사 단어는 *** 처리.

B. 점수 배점 (Scoring)

로직: 남은 시간에 비례하여 점수 획득.

공식: (남은 시간 / 전체 시간) * 최대 점수

빨리 맞힐수록 고득점. 못 맞히거나 스킵 시 0점.

C. 라운드 종료 조건
Time Over: 제한 시간 종료.

All Clear: 모든 생존 플레이어가 정답을 맞힘 (즉시 종료).


Vote Skip: 플레이어들의 /skip 투표가 설정된 비율을 넘김 (영상 오류 대비).

D. 라운드 결과 (Round Result)
3~5초간 오버레이 팝업.

내용: 정답 곡 제목, 가수, 앨범 커버(썸네일), 정답자 목록.

이후 자동으로 다음 라운드 시작.

4. 최종 결과 (Game Over - Result Screen)
모든 라운드가 종료된 후 나타나는 화면입니다.

A. 순위표 (Podium)
시상대: 1등, 2등, 3등 아바타가 단상 위에 올라가 있음.

전체 순위: 아래 리스트로 전체 플레이어 점수 표시.

광고 노출: 결과 확인 시 시선이 머무는 곳에 배너 광고 배치 (수익화 포인트).

B. 네비게이션
[로비로 돌아가기]: 다시 대기실로 이동하여 설정 변경 후 재시작.

[나가기]: 메인 화면으로 이동.

5. 기술 및 데이터 구조 (Technical Specs)
A. 데이터 관리 (No-DB Strategy)
유저 리스트: 서버 DB에 저장하지 않음. 유저가 JSON/TXT 파일로 개인 소장.

게임 세션: 메모리(RAM) 상에서만 일시적으로 존재하고 게임 끝나면 휘발됨. -> 서버 비용 극소화.

B. 핵심 기술 스택 (권장)
Frontend: HTML5, CSS3, JavaScript (React 등).

Backend: Node.js (가볍고 빠름).

Socket: Socket.io (실시간 채팅 및 타이머 동기화 필수).

API: YouTube IFrame API (영상 제어).

이 명세서는 **작성자님의 기획 의도(Showdown 방식 리스트, 스크리블 스타일, 수익화 목표)**를 완벽하게 반영하여 정리한 것입니다.
